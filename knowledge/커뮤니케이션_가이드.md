# 커뮤니케이션 가이드 (Slack · 회의 · 메일 · 보고)

> 상태: 초안 (2026-10-29, 온보딩 플랫폼 MVP 용). 회의 요일·시간과 회의록 위치는 운영자가 채운다. 확인되지 않은 값은 `[[확인 필요]]`.

## 1. 원칙

- **공개 채널 우선.** 업무 대화는 DM 보다 채널 스레드에 남긴다. 나중에 합류한 사람이 맥락을 찾을 수 있어야 한다.
- **한 주제 한 스레드.** 채널 본문에는 요지 한 줄, 세부는 스레드.
- **결정은 글로 남긴다.** 회의·통화로 정한 것도 채널이나 문서에 "무엇을, 왜, 언제" 적는다.
- 고객·발주처와의 공식 소통은 **메일**, 내부 소통은 **Slack**.

## 2. Slack 사용 규칙

| 항목 | 규칙 |
|---|---|
| 채널 선택 | 용도별 채널(`도구_세팅_가이드.md` §3). 애매하면 `#general` 이 아니라 가장 가까운 업무 채널 |
| `@channel` / `@here` | `@channel` 은 공지 채널에서 운영자·팀장만. `@here` 는 근무시간 안에서 즉시 대응이 필요할 때만 |
| 개인 멘션 | 답이 필요한 사람에게만. 참고용이면 멘션 없이 스레드에 남긴다 |
| DM | 개인 사정, 1:1 피드백, 민감한 내용. 업무 결정은 DM 에서 끝내지 않고 채널에 요약 |
| 응답 기대 | 근무시간 안 채널 멘션은 당일 안에. 긴급(교육 현장 장애)은 전화 |
| 상태 표시 | 교육 현장·외근·휴가는 상태 메시지로 표시 |
| 외부 공유 채널 | `#prj-<기관명>` 처럼 발주처가 들어와 있는 채널에는 내부 메모·비용 얘기를 쓰지 않는다 |
| 파일 공유 | 보고서·명단은 Slack 에 올리지 않고 Drive 링크로. 자격증명·키는 어디에도 올리지 않는다 |

## 3. 회의

- 주간 회의: `[[확인 필요: 요일·시간]]`. 안건은 전날까지 채널에 올린다.
- 회의록 위치: `[[확인 필요: Drive 폴더 또는 채널]]`. 형식은 **결정 사항 · 담당 · 기한** 세 줄을 먼저 쓰고 논의는 아래에.
- 결정 기록은 번복할 때 지우지 않고 취소선으로 남긴다 (`AGENTS.md` §8 방식).
- 멘토 면담(공통 트랙 C5·C10, 교육 트랙 E9·E13·E16)은 30분 기본. 신입이 "기억할 점 3줄" 을 온보딩 플랫폼 과제에 제출한다.

## 4. 메일

- 발주처·고객에게는 회사 메일로만 보내고, 담당 팀장을 참조에 넣는다.
- 제목은 `[기관명] 과정명 — 용건` 형식. 첨부 보고서는 최종본만, 수정본 파일명(`_수정본`)으로 보내지 않는다.
- 서명 형식은 `도구_세팅_가이드.md` §5.

## 6. 신입의 질문 경로

1. 온보딩 플랫폼 에이전트에게 먼저 묻는다. 사내 문서를 인용해 답하고, 없으면 "찾지 못했다" 고 말한다.
2. 문서에 없으면 에이전트가 **담당자에게 전달**을 제안한다. 확인하면 담당자 인박스로 가고, 답변은 신입 인박스와 문서 초안으로 돌아온다.
3. 급하면 멘토에게 Slack 스레드로. 멘토가 모르는 영역은 사람 디렉터리에서 담당자를 찾는다.
