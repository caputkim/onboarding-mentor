# 근무 규정과 보안 규칙 요약

> 상태: 초안 (2026-10-29, 온보딩 플랫폼 MVP 용). 근태·휴가·경비는 회사 취업규칙이 정본이며, 아래는 법정 기준과 현재 관행을 적은 요약이다. 운영자 확인 후 확정하고, 다른 항목은 이 문서를 고친다. 확인되지 않은 값은 `[[확인 필요]]`.

## 1. 근태

| 항목 | 내용 |
|---|---|
| 근무시간 | 주 40시간 (근로기준법 기준). 출퇴근 시각·점심시간은 `[[확인 필요]]` |
| 근무 장소 | 사무실 기본. 재택·유연근무 가능 여부와 신청 방법은 `[[확인 필요]]` |
| 교육 현장 근무 | 교육일에는 현장 출근. 이동 시간·조기 출발은 근무로 본다. 현장 일정은 `#edu-운영` 에 미리 공유 |
| 지각·조퇴 | 사전에 Slack 으로 팀장에게 알린다 |

## 2. 휴가

- 연차: 근로기준법 기준으로 1년 미만은 한 달 개근마다 1일, 1년 이상은 15일. 회사 부여 기준이 다르면 `[[확인 필요]]`.
- 신청 방법: Slack `#휴가신청` 채널에 **휴가 날짜와 사유**를 게시한다. 팀장이 게시글에 이모지로 승인한다. 반차도 같은 방식이다.
- 사전 신청 기한: 3일 이상 연속 휴가는 시작 **2주 전**, 그 외는 **3일 전**까지.
- 긴급한 경우(병가 등)는 당일 아침 팀장에게 먼저 연락하고 사후에 게시한다.
- 교육 운영일에는 강사·보조강사가 동시에 비지 않도록 팀 안에서 먼저 조정한다.

## 3. 경비

- 교육 출장 교통비·식비·숙박비는 영수증을 모아 정산한다. 정산 주기·한도·제출 방법은 `[[확인 필요]]`.
- 법인카드 사용 기준은 `[[확인 필요]]`.
- 교육 장비·교재 구매는 담당자 사전 승인 후 진행한다.

## 4. 계정 보안

1. 회사 메일·Slack·GitHub·AWS 모두 **2단계 인증**을 켠다.
2. 비밀번호는 비밀번호 관리자를 쓰고 서비스마다 다르게 만든다. 재사용·공유 금지.
3. 노트북은 디스크 암호화와 화면 잠금(5분 이내)을 켠다. 분실 시 즉시 운영 담당자에게 알린다.
4. 퇴사·역할 변경 시 계정은 운영자가 회수한다. 개인 계정으로 회사 자료를 옮기지 않는다.

## 5. 자격증명 원칙 (AWS·API 키)

AWS 계정 관리 지침(`AWS 클라우드 관리 프로젝트 에이전트 지침`)의 원칙을 전 직원이 따른다.

- 자격증명은 **읽지도, 출력하지도, 커밋하지도 않는다.** AWS 는 `~/.aws/config` 의 프로필로만 쓴다.
- 회사 프로필(`nxtcloud`, 고객 계정 프로필)과 개인 프로필을 섞지 않는다. 대상이 모호하면 작업 전에 묻는다.
- 명령에는 `--profile` 을 명시하고, **변경 전에 대상 계정을 확인**한다. 삭제·교체 같은 파괴적 작업은 직전에 다시 확인한다.
- `.env`, `accessKeys.csv`, Terraform state(ExternalId 평문 포함)는 리포·동기화 폴더·채팅에 두지 않는다.
- API 키(Anthropic, LLM Gateway 발급 키)는 Secrets Manager 나 `.env` 에만 두고 화면·문서에 적지 않는다. 유출이 의심되면 **먼저 비활성화**하고 담당자에게 알린다.

## 6. 고객 자료와 개인정보

- 참여자 명단·출석부·연락처·만족도 원자료는 **사업 폴더 안에서만** 다룬다. 외부 공유 전에 발주처 요구사항을 확인하고, 불필요하면 소속·성명만 남긴다.
- 결과보고서에 실명·이메일을 새로 만들어 넣지 않는다. 실적 수치(만족도·인원·자격증 취득 수)는 근거 자료가 없으면 `[[추후기입]]` 으로 비워 둔다.
- Drive 원본은 직접 편집하지 않는다. 로컬 수정본에서 작업하고 백업을 남긴 뒤 `drive_sync.py` 로 반영한다.
- 온보딩 플랫폼 지식베이스에는 명단·연락처 파일을 올리지 않는다. 수집 스크립트가 파일명(`출석부`, `명단`, `연락처`, `개인정보`, `계약서`, `견적`)으로 거르고, 본문에 이메일·전화가 몰린 섹션은 제외한다.
- 외부 AI 도구에 고객 개인정보·계약 조건을 입력하지 않는다. 사내 LLM Gateway 를 통한 호출도 요청 본문에 개인정보를 넣지 않는다.

## 7. 사고 대응

| 상황 | 할 일 |
|---|---|
| 키·비밀번호 유출 의심 | 즉시 비활성화 → 클라우드 담당자·운영자에게 알림 → 교체 |
| 노트북 분실 | 운영자에게 알림 → 회사 계정 비밀번호 변경 → 기기 원격 잠금 `[[확인 필요: 관리 도구]]` |
| 고객 자료 오발송 | 발신 취소 시도 → 팀장에게 즉시 보고 → 발주처 통보 여부는 팀장 판단 |
| Drive 원본 손상 | `_백업_drive_…` 파일 또는 Drive 웹 **버전 관리**로 복구 |

## 8. 자주 묻는 질문

- **휴가는 몇 일인가?** 법정 기준은 위 §2. 회사 기준은 `[[확인 필요]]` — 운영 담당자에게 묻는다.
- **교육 현장에 갈 때 교통비는?** 영수증 정산(§3). 한도·방법은 운영 담당자.
- **AWS 키를 동료에게 Slack DM 으로 보내도 되나?** 안 된다. 담당자가 IAM 사용자·프로필을 따로 발급한다.
- **보고서에 참여자 이메일을 넣어야 하나?** 발주처가 요구할 때만. 기본은 소속·성명.
