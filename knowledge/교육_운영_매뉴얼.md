# 교육 운영 매뉴얼 (사전 준비 → 현장 → 보고서 → 동기화)

> 상태: 초안 (2026-10-29, 온보딩 플랫폼 MVP 용). 결과보고서 규칙은 `AGENTS.md`(교육 결과보고서 작업 지침)가 정본이고 이 문서는 교육 한 건의 전체 흐름을 잇는다. 확인되지 않은 값은 `[[확인 필요]]`.

## 0. 한눈에 보기

```
① 계약·사전 협의 → ② 커리큘럼 공지(curriculum.md) → ③ 명단·출석부·교육 환경 준비
→ ④ 현장 운영(출석·사진·실습 지원) → ⑤ Slack 만족도 조사 → ⑥ 결과보고서 작성
→ ⑦ Drive 동기화 → ⑧ 작업메모 갱신 → ⑨ 사후관리(양식 B 일 때)
```

역할: **강사**(강의·실습 진행), **보조강사**(실습 지원·질문 대응·사진·출석), **운영**(발주처 소통·보고서·정산). 소규모 교육은 한 사람이 둘을 겸한다.

## 1. 계약·사전 협의

- 발주처 유형: 대학 캠퍼스타운 사업단, SW중심대학사업단, 대학 부서(교직원·학생 대상). 유형에 따라 **보고서 양식 소유권**이 다르다(발주처 지정 / 자사 양식). 사전 협의 때 양식·제출 기한·첨부 요구(사진, 출석부, 만족도)를 확인한다.
- 사업 폴더를 만든다: `YYMM_기관명_과정명/` + `결과보고서/`, `사진/<n일차>/`, `출석부/`, `curriculum.md`.

## 2. 커리큘럼 공지

- 참가자에게 사전 공지한 커리큘럼을 `curriculum.md` 에 그대로 보관한다. 여기에는 보통 "진행 상황에 따라 변경될 수 있습니다" 단서가 붙는다.
- 이 파일은 보고서의 **일차별 강의계획(계획)** 표의 출처다. 실제 운영과 달라져도 덮어쓰지 않는다 — 계획과 실적의 차이를 보여주는 것이 그 표의 목적이다.

## 3. 명단·출석부·교육 환경

| 준비물 | 내용 |
|---|---|
| 참여자 명단 | 발주처에서 받는다. 사업 폴더 밖으로 내보내지 않는다 |
| 출석부 | 일차별. 수료 기준(출석률 등)은 발주처와 합의 `[[확인 필요: 기본 수료 기준]]` |
| 실습 계정 | AWS 실습이면 교육용 계정·IAM 사용자. 발급·회수는 클라우드 담당자 |
| Bedrock 호출 | **LLM Gateway 콘솔**(`console.bedrock.nxtcloud.kr`)에서 교육 생성 → 명단 CSV 로 키 일괄 발급. 교육 총 한도와 1인 한도를 정한다. 키 회수·한도 변경은 최대 60초 뒤 반영, 한도 초과는 즉시 차단(`422 budget_exceeded`) |
| 기타 도구 | AWS PartyRock·Skill Builder 는 수강생 개인 계정, Kiro 는 구독 안내, Canva 는 교육용 계정 `[[확인 필요]]` |
| 장비 | 강의 노트북, 어댑터, 포인터, 현장 Wi-Fi 확인(대학 네트워크가 특정 포트를 막는 경우가 있다) |

수강생 안내문(가입·키 사용법)은 LLM Gateway `포털 사용법` §7 의 학생 안내문을 쓴다.

## 4. 현장 운영

- **출석**: 시작 전·점심 후 2회 체크. 미수료 예상자는 당일 운영 담당에게 알린다.
- **사진**: 일차별로 강의·실습·단체 사진을 찍어 `사진/<n일차>/` 에 올린다. 보고서 첨부는 한글에서 셀 배경 그림으로 직접 넣으므로 가로 사진을 넉넉히 찍는다. 얼굴이 크게 나온 사진은 쓰지 않는다.
- **실습 지원**: 막힌 수강생은 손들기 대신 Slack·채팅으로 받고, 같은 질문이 3번 나오면 전체에게 공지한다.
- **시간 운영**: 세부일정표에 쓸 수 있도록 실제 시작·종료 시각과 변경 사항을 메모한다. 비고 어휘는 `이론` · `실습` · `이론, 실습` · `안내` · `평가` · `발표` · `-`.
- **당일 보고**: `#edu-운영` 에 출석 인원, 사진 업로드, 특이사항을 남긴다.

## 5. 만족도 조사

- 마지막 일차 종료 전에 Slack(또는 발주처 지정 도구)으로 설문 링크를 공유한다. 보고서 첨부 항목이 `Slack을 통한 만족도 조사 실시` 이므로 안내 화면을 캡처해 둔다.
- 결과는 점수(5점 만점)와 좋았던 점·아쉬웠던 점 원문을 받는다. 점수 표기는 `4.79점 / 5.0점 (33명 응답)`.
- 응답자 수·점수는 **원자료로만** 보고서에 쓴다. 추정하지 않는다.

## 6. 결과보고서

1. 양식 선택: 새 보고서는 양식 A(캠퍼스타운 표준). 발주처 지정이면 양식 B(사후관리 포함). 구형 완료보고서(양식 C)는 발주처 요구 시만.
2. 같은 발주처의 직전 보고서를 레퍼런스로 삼되, **이전 사업의 기관명·수치·고유명사가 남지 않았는지** 반드시 확인한다(실제 사고 사례).
3. 수치 정합성: 참여인원 = 명단 행 수, 수료인원 = 명단 − 미수료, 만족도 3곳 일치, 일수·총시간 = 일정표.
4. 일정 섹션 세 개는 "계획 vs 실적" 축으로 쓴다: 일차별 강의계획(계획, `curriculum.md`), 세부 진행 내용(실적 요약), 교육과정 세부일정표(실적 상세).
5. 편집은 로컬 수정본에서 스크립트로: `doctext.py` 읽기 → `hwpx_edit.py --dry` → 치환 → 무결성 검증. 원본을 덮어쓰지 않는다.
6. 제출 전 `grep '\[\['` 로 `[[추후기입]]` 전량 제거 확인.

세부 규칙·체크리스트·과거 사고는 `AGENTS.md` §2·§4·§5·§9.

## 7. Drive 동기화

```bash
python3 _보고서도구/drive_sync.py 로컬/수정본.hwpx "$DRIVE/원본.hwpx"        # 검사·백업까지
python3 _보고서도구/drive_sync.py 로컬/수정본.hwpx "$DRIVE/원본.hwpx" --yes  # 반영
```

백업 경로와 변경 요약을 `#edu-보고서` 에 남긴다. 무결성 검사 실패 시 올리지 않는다. 되돌리기는 백업 복사 또는 Drive 웹 버전 관리.

## 8. 작업메모

사업 폴더의 `결과보고서/작업메모.md` 에 채운 것·남은 것·판단 근거를 적는다. 다음 사람(또는 다음 세션)이 상태를 알 수 있어야 한다.

## 9. 사후관리 (양식 B)

자격증 과정은 기준일을 정해 `자격증 취득 현황` 표(취득 / 응시 신청 / 준비 중 / 미응시·미확인 / 전체)를 채운다. 합계가 전체 참가자 수와 같아야 한다. 취득 수는 수강생 확인 자료가 있을 때만 적는다.
