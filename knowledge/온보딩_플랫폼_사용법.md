# 온보딩 플랫폼 사용법

> 상태: 2026-10-29 MVP 기준. 화면이 바뀌면 이 문서를 고친다.

## 1. 가입·로그인

- 회사 메일(`@nxtcloud.kr`)로만 가입할 수 있다. 다른 도메인은 거부된다.
- 비밀번호는 8자 이상, 영문과 숫자를 섞는다. 역할(구성원·멘토·운영자)은 운영자가 지정한다.
- 비밀번호 재설정 기능은 아직 없다. 잊으면 운영자에게 요청한다.

## 2. 신입 화면

| 화면 | 내용 |
|---|---|
| 홈 | D+n 일차, 진행률, 오늘까지 할 일, 이번 주 과제, 최근 피드백, 보낸 질문 |
| 여정 | 트랙·단계별 전체 플랜. 각 과제의 상태와 기한 |
| 과제 | 설명·제출물·평가 기준·참고 문서. **시작 → 완료** 또는 **막힘**(사유 기록). 제출물을 올리면 에이전트가 평가 기준 항목별로 통과·보완을 판정한다. 보완이면 고쳐서 다시 제출한다 |
| 대화 | 에이전트와 채팅. 대화 원문은 본인만 볼 수 있다. 멘토·운영자는 진행률·주제 집계·전달된 질문만 본다 |
| 인박스 | 담당자에게 전달한 질문과 답변 |

## 3. 에이전트에게 물을 수 있는 것

- **사내 사실**: 규정, 절차, 도구 위치, 과거 보고서 내용. 문서를 읽고 `[문서 › 섹션]` 으로 인용해 답한다. 문서에 없으면 "찾지 못했다" 고 말한다.
- **내 플랜**: 오늘 할 일, 이번 주, 특정 과제 내용. "C2 완료 처리해 줘" 처럼 상태 변경도 된다.
- **누구에게 물을지**: 사람 디렉터리에서 담당 영역으로 찾아 준다. 연락처는 알려주지 않는다.
- **담당자에게 전달**: 문서에 답이 없으면 전달을 제안한다. 버튼으로 확인해야 실제로 전달된다. 답변은 인박스로 오고, 운영자가 그 답변을 문서 초안으로 수락하면 다음 사람은 바로 답을 받는다.
- 못 하는 것: 자격증명·연락처·인사 평가에 관한 질문, 일반 상식 수준을 넘는 사내 사실의 추측.

## 4. 과제 상태

`할 일 → 진행 중 → 제출됨 → 완료` 또는 `막힘`. 제출은 "제출됨" 에서 에이전트 검토를 거쳐, 통과면 완료가 된다. 멘토가 제출물에 메모를 남길 수 있다.

## 5. 멘토·운영자

- 멘토: 담당 신입의 진행률, 기한 초과, 막힘 사유, 최근 제출 판정, 월요일 주간 요약. 인박스에서 전달된 질문에 답한다.
- 운영자: 온보딩 개설(신입·멘토·트랙·시작일), 플랜 가져오기(`plans/*.md`), 지식 문서 관리(동기화·가시성·개인정보 플래그), 사람 디렉터리, 공백 리포트(주제별 질문·미응답 집계, 문서 초안 수락).

## 6. 지식 문서 추가

운영자가 맥에서 수집 스크립트(`ingest/ingest.py`)로 Drive·리포의 hwpx·docx·md·pdf 를 올린다. 서버가 섹션을 나누고 요약·태그·개인정보 의심 여부를 판정한다. 명단·연락처 파일은 파일명으로 걸러지고, 개인정보 의심 문서는 운영자가 확인하기 전까지 답변에 쓰지 않는다.
