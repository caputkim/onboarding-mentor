# 넥스트클라우드 회사소개

> 상태: 초안 (2026-10-29, 온보딩 플랫폼 MVP 용). 리포에 있는 결과보고서·설계 문서·제품 README 에서 확인되는 내용으로 작성했다. 운영자 확인 후 확정하며, 사실과 다른 항목은 이 문서를 고친다. 확인되지 않은 값은 `[[확인 필요]]` 로 남겼다.

## 1. 한 줄 소개

주식회사 넥스트클라우드는 대학·공공기관을 주 고객으로 **클라우드·AI 교육**을 운영하고, **AWS 계정 운영(MSP)** 과 **교육 현장을 돕는 소프트웨어 개발**을 함께 하는 회사다. 회사 도메인은 `nxtcloud.kr` 이며, 문서·메일·Drive 는 Google Workspace, 소통은 Slack, 코드는 GitHub(`nxtcloud-org`)에 둔다.

작은 조직이라 한 사람이 두 축 이상에 걸쳐 일한다. 신입은 먼저 공통 트랙으로 회사 전체를 익히고, 직군 트랙(교육 → 이후 MSP·개발)으로 들어간다.

## 2. 사업 세 축

| 축 | 고객 | 제공하는 것 | 대표 산출물 |
|---|---|---|---|
| 교육 | 대학 캠퍼스타운 사업단, SW중심대학사업단, 대학 교직원·학생 | 클라우드·AI 교육 과정의 기획·강의·실습 운영 | 교육 운영 + 결과보고서(완료보고서) |
| MSP | 고객 기관의 AWS 계정 | 계정 구조 설계, 비용·권한 관리, 실습용 Bedrock 접근(LLM Gateway) | 운영 중인 계정과 런북 |
| 개발 | 교육 현장(강사·수강생)과 고객 기관 | 교육 운영을 돕는 자사 서비스와 고객 맞춤 서비스 | CertiNavigator, LLM Gateway 콘솔, AI Makers, AI Professor, 온보딩 플랫폼 |

### 2.1 교육

- 과정 유형: 생성형 AI 리터러시, AI 초·중급(바이브코딩), AWS 자격증(CLF·AIF) 준비, Amazon Bedrock·Kiro·Agentic AI 개발특강. 자세한 과정 목록과 교안 위치는 `교육_과정_카탈로그.md`.
- 운영 흐름: 사전 커리큘럼 공지 → 현장 운영(출석·사진·실습 지원) → Slack 만족도 조사 → 결과보고서 → Drive 동기화. 절차는 `교육_운영_매뉴얼.md`, 보고서 규칙은 `AGENTS.md`(교육 결과보고서 작업 지침).
- 최근 사례(리포의 보고서 기준): 광주대 「AI를 쓰면 더 편해지는 대학생활」, 구미대 교원 대상 AI 능력 함양, 우송대 AWS CLF 자격증명 교육, 중앙대 캠퍼스타운 서남권 AI 풀스택(AI 초·중급), 서울시립대 캠퍼스타운, 국민대 캠퍼스타운 중급·중급심화, 국민대 SW중심대학사업단 AI 플랫폼 개발특강.

### 2.2 MSP (AWS 계정 운영)

- 회사 계정과 고객·테넌트 계정을 **AWS CLI 프로필**로 분리해 다룬다. 회사 프로필은 `nxtcloud`, 고객 계정 프로필은 기관별로 둔다. 개인 프로필과 회사 프로필은 섞지 않는다.
- 자격증명은 읽지도 출력하지도 커밋하지도 않는다. 변경 전에 대상 계정을 확인하고, 파괴적 작업 전에는 다시 확인한다. 규칙 원문은 `AWS 클라우드 관리 프로젝트 에이전트 지침`.
- 교육용 Bedrock 접근은 **LLM Gateway**(`bedrock.nxtcloud.kr`)가 담당한다. 테넌트(고객 AWS 계정)마다 역할 하나만 만들고, 비용은 그 계정에 청구된다.

### 2.3 개발

| 서비스 | 용도 | 상태 |
|---|---|---|
| CertiNavigator (`certi.nxtcloud.kr`) | AWS 자격증 과정 수강생의 학습 지원 | 운영 중 |
| LLM Gateway (`bedrock.nxtcloud.kr`) | 여러 AWS 계정의 Bedrock 을 base URL 하나로 제공. 교육·키·예산 관리 콘솔 포함 | 운영 중 |
| AI Makers | 캔바 강의자료를 보며 수업을 진행하고 수강생 작업물 URL 을 모으는 수업 도우미 | 운영 중 (광주대) |
| AI Professor | 강의자료 기반 AI 조교 서비스 | 1단계 설계 중 |
| 온보딩 플랫폼 | 신입의 첫 90일 플랜·과제·질문을 돕는 사내 도구 | MVP |

자세한 설명은 `자사_제품_서비스.md`.

## 3. 일하는 방식 요약

- 문서는 Google Drive, 코드와 운영 지침은 GitHub 리포의 `AGENTS.md`·`README.md` 에 둔다. 규칙을 고칠 때는 정본 문서 한 곳만 고친다.
- 고객 자료(참여자 명단·출석부·연락처)는 보고서 밖으로 나가지 않는다. 실적 수치는 추정하지 않고 근거 자료가 없으면 `[[추후기입]]` 으로 비워 둔다.
- 결정은 날짜와 근거를 붙여 기록하고, 번복할 때는 취소선으로 남긴다.
