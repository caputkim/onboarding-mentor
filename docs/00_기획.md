## 1. 한 줄 정의

온보딩 챗봇이 아니라, 신입의 첫 90일을 **오늘 할 일 · 막힌 질문 · 연습 과제 · 물어볼 사람** 으로 같이 걷는 동료.
회사 입장에서는 **신입의 질문 로그로 사내 문서 공백을 찾아내는 장치.**

## 3. 전제와 문제

### 사내 자료로 파악한 전제
- 사업축 3개: 공공·교육기관 대상 클라우드/AI 교육, AWS MSP, 개발. 작은 조직이라 한 사람이 둘 이상에 걸침.
- 도구: Google Workspace(Drive·메일), Slack, GitHub, AWS 멀티계정, Terraform·CDK, Next.js·Python.
- 이미 있는 자산
  - `_보고서도구/doctext.py` — hwpx·docx 텍스트 추출 (지식 파이프라인의 핵심 부품)
  - `AGENTS.md` — 결과보고서 작업 규칙·체크리스트·과거 사고 사례 (교육 트랙 코치의 평가 기준)
  - `0000_결과보고서_모음/` 과 사업 폴더들 — 레퍼런스 문서
  - `cloud-management/` — AWS 계정·프로필 규칙, 자격증명 금지 원칙

### 아직 확인하지 않은 가정
- 연간 신입은 소수, 멘토링은 비공식 1:1.
- 온보딩 플랜·사람 디렉터리 같은 구조화 문서는 없음 → `plans/` 초안이 첫 버전.
- 근무 규정·보안 규칙·회사소개 문서의 존재 여부 → ~~플랜에 `[[추후기입]]` 으로 비워 둠~~ 2026-10-29 `knowledge/` 에 초안 8건을 쓰고 플랜이 참조하게 함. 실제 규정과 다른 값은 운영자가 고친다 (`[[확인 필요]]` 표시).

### 신입이 겪는 문제
- 사업 세 축이 섞여 있어 회사 전체 그림을 잡기 어려움.
- 지식이 사람 머릿속·Slack·Drive 에 흩어져 있어 "누가 아는지"부터 물어야 함.
- 계정·채널·폴더 세팅이 체크리스트 없이 구두로 진행됨.
- 연습 없이 바로 보조강사나 보고서 작성에 투입됨.
- 질문이 멘토 한 명에게 몰려 양쪽 다 부담.

### 회사가 겪는 문제
- 온보딩 품질이 멘토 개인에게 달려 있고, 진행 상황은 물어봐야 앎.
- 문서화 안 된 지식은 퇴사와 함께 사라짐.
- 교육을 파는 회사의 자사 온보딩이 비체계적. 잘 만들면 교육 콘텐츠·레퍼런스가 됨 (단, 제품화는 현재 범위 밖).

## 4. 사용자 · 트랙 · 에이전트 역할

### 사용자 세 종류
| 사용자 | 하는 일 | 화면 |
|---|---|---|
| 신입 | 오늘 할 일 확인, 질문, 과제 제출, 피드백 확인 | 홈 · 대화 · 여정 · 과제 |
| 멘토 | 담당 신입 진행률·막힘 확인, 주간 요약 읽기, 에스컬레이션 응답 | 멘토 현황 · 에스컬레이션 |
| 운영자 | 온보딩 개설, 플랜·지식 소스·사람 디렉터리 관리, 문서 공백 리포트 | 콘솔 |

### 트랙
| 트랙 | 핵심 학습 | 90일 단독 과업 | 상태 |
|---|---|---|---|
| 공통 | 회사·사업 이해, 도구 세팅, 규정, 사람 디렉터리, AWS 계정 구조 | 없음 (2주차 내 완료) | `plans/공통트랙.md` 초안 |
| 교육 | 발주처·과정 유형, 보고서 양식·문체, 계획 vs 실적, 보고서 도구, 교육 운영 절차 | 결과보고서 1편 초안 단독 작성 | `plans/교육트랙.md` 초안 |
| MSP | 멀티계정·프로필 규칙, 비용·보안 운영, 장애 대응 | 월간 비용 리포트 1건 | 추후 |
| 개발 | 사내 리포 구조, 배포 패턴, 코드 리뷰 문화 | 기능 1개 PR 머지 | 추후 |

### 에이전트 4역할
구현은 **오케스트레이터 하나 + 도구 묶음** 으로 시작한다. 역할은 시스템 프롬프트의 섹션과 도구 집합으로만 나뉜다.
처음부터 멀티에이전트로 쪼개지 않는다.

| 역할 | 하는 일 | 쓰는 도구 |
|---|---|---|
| 가이드 | 플랜 기준 오늘·이번 주 할 일, 완료 체크, 막힘 감지, 멘토용 주간 요약 | 플랜·과제 DB |
| 지식 | 사내 문서를 찾아 **출처를 붙여** 답변. 근거 없으면 모른다고 하고 연결 역할로 넘김 | 문서 카탈로그·본문 읽기, 사람 디렉터리 |
| 코치 | 트랙별 과제 제시와 제출물 검토. 교육 트랙은 `AGENTS.md` 체크리스트가 평가 기준 | 과제 루브릭, 제출물 |
| 연결 | 답 못 한 질문을 분류해 적임자에게 전달. 답이 오면 문서 초안으로 지식베이스 반영 제안 | 에스컬레이션, 질문 로그, 문서 초안 |

**연결 역할이 핵심 루프다.** 에이전트가 못 답한 질문 = 회사에 없는 문서. 이것을 운영자에게 보여주는 것이
지식베이스를 자라게 하는 유일한 장치다.
