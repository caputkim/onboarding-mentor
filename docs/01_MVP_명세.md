# MVP 기능 명세

> 작성 2026-10-29. `00_기획.md` §2 의 확정 방향을 전제로 한다.
> 범위 밖 항목은 §1 "제외" 에 명시해 두고, 구현 중 끼워 넣지 않는다.

## 1. 범위

### 포함 (MVP)
- 웹 앱 하나에 신입·멘토·운영자 화면. 이메일·비밀번호 로그인과 회원가입 (nxtcloud.kr 도메인 한정).
- 트랙: **공통 + 교육.** 플랜은 `plans/*.md` 를 콘솔에서 가져와 템플릿으로 저장.
- 에이전트: 가이드·지식·코치·연결 4역할을 가진 **단일 오케스트레이터**, 스트리밍 채팅.
- 지식 소스: Drive 화이트리스트 폴더 (hwpx·docx·md), GitHub 지정 리포의 md, 콘솔 수동 업로드.
- 과제 제출과 코치 검토 (텍스트·마크다운 제출. 파일은 링크로).
- 에스컬레이션: 미응답 질문 → 담당자 지정 → 답변 → 문서 초안 제안.
- 멘토 주간 요약 (원문 없이 진행률·막힘·주제 집계로 생성).
- 운영자 콘솔: 온보딩 개설, 플랜 가져오기, 지식 소스 동기화·목록·가시성, 사람 디렉터리, 문서 공백 리포트.

### 제외 (2단계 이후)
- Slack 봇·알림, 이메일 알림.
- MSP·개발 트랙, 샌드박스 AWS 실습 검증.
- Slack 채널 인덱싱, 벡터 임베딩 검색.
- hwpx 파일 자체 업로드·편집 (제출물은 텍스트·링크만).
- 자격증 연계(CertiNavigator), 다국어, 모바일 최적화.

## 2. 사용자 스토리

### 신입
- 로그인하면 **오늘 할 일**과 이번 주 남은 항목, 전체 진행률이 보인다.
- 할 일을 누르면 설명·참고 문서·제출 방법이 보이고, 완료 체크나 제출을 할 수 있다.
- 채팅에서 "결과보고서 양식 B 가 뭐예요" 같은 질문을 하면 **출처가 붙은** 답을 받는다.
- 에이전트가 모르는 질문이면 "담당자에게 전달할까요" 를 묻고, 동의하면 전달된다. 전달될 질문 문구를 미리 볼 수 있다.
- 과제를 제출하면 체크리스트 기준의 피드백을 받고, 고쳐서 다시 제출할 수 있다.
- 내 대화는 나만 본다는 안내가 화면에 있다.

### 멘토
- 담당 신입의 **진행률·기한 초과·막힘(BLOCKED) 항목**을 한눈에 본다. 대화 원문은 보이지 않는다.
- 매주 월요일 주간 요약을 본다. 요약은 과제 상태와 질문 주제 집계로만 구성된다.
- 나에게 온 에스컬레이션에 답하면, 신입에게 답이 전달되고 문서 초안 제안이 운영자에게 간다.
- 제출물에 메모를 남길 수 있다 (코치 피드백과 별도).

### 운영자
- 신입·멘토·트랙·시작일을 지정해 온보딩을 개설하면 플랜이 기한과 함께 펼쳐진다.
- `plans/*.md` 를 가져와 트랙 템플릿을 만들고, 항목을 수정한다.
- 지식 소스를 동기화하고, 문서 목록·요약·가시성을 확인·수정한다. 개인정보 필터에 걸린 파일을 본다.
- 사람 디렉터리(누가 무엇을 담당)를 편집한다.
- **문서 공백 리포트**에서 미응답 질문 주제 집계와 에스컬레이션 답변 기반 문서 초안을 보고 수락·거절한다.
- 전체 온보딩 현황(진행률·지연·에스컬레이션 대기)을 본다.

## 4. 에이전트 설계

### 4.1 구성
단일 오케스트레이터. 요청마다 다음을 조립해 Claude 를 호출하고, 도구 호출 루프는 SDK 도구 러너가 돈다.

```
[시스템 프롬프트 — 캐시 가능한 순서로]
 1. 정체성·답변 정책·안전 규칙                     (고정)
 2. 역할별 지침: 가이드 / 지식 / 코치 / 연결       (고정)
 3. 문서 카탈로그: 문서 id · 제목 · 한 줄 요약 · 태그 (동기화 때만 바뀜)
 4. 사람 디렉터리 요약                              (드물게 바뀜)
 ---- cache_control 경계 ----
 5. 이 신입의 맥락: 트랙, 오늘 날짜, 이번 주 할 일, 막힘 항목, 에이전트 메모리 요약 (매 요청)
[메시지] 대화 이력 (최근 N턴 + 요약)
[도구] §4.3
```

- 1~4 는 요청 간 동일하므로 프롬프트 캐시가 먹는다. 5 부터는 가변.
- 카탈로그는 문서 수백 건까지 그대로 넣는다 (제목+한 줄 요약이면 문서당 수십 토큰). 넘치면 트랙별로 나눈다.

### 4.2 답변 정책 (시스템 프롬프트 1번 섹션의 핵심)
- 사내 사실(규정·절차·양식·담당자)은 **도구로 읽은 문서를 인용**해서만 답한다. 인용할 문서가 없으면 "사내 문서에서 찾지 못했다" 고 말하고 에스컬레이션을 제안한다.
- 일반 기술 지식(AWS 개념, 한글 문법 등)은 인용 없이 답해도 되지만, 사내 규칙과 충돌할 수 있으면 사내 문서를 우선한다.
- 자격증명·비밀번호·개인 연락처는 어떤 경로로도 다루지 않는다. 요청받으면 거절하고 담당자를 안내한다.
- 인사·급여·평가에 관한 질문은 답하지 않고 담당자 연결만 한다.
- 개조식·반말 금지. 신입이 이해할 수 있는 수준으로, 용어는 처음 나올 때 풀어 쓴다.
- 에스컬레이션은 반드시 신입 동의 후에만 실행한다. 전달될 문구를 먼저 보여준다.

### 4.3 도구

| 도구 | 입력 | 출력 | 비고 |
|---|---|---|---|
| `get_plan` | 범위 `today\|week\|all` | 과제 목록(id·제목·상태·기한·유형) | 가이드 |
| `get_task` | taskInstanceId | 설명, 참고 문서, 루브릭, 제출 이력 | 가이드·코치 |
| `update_task_status` | taskInstanceId, status, note? | 갱신 결과 | `DONE` 은 제출물이 필요한 유형이면 거부 |
| `search_documents` | query, trackSlug? | 문서 id·제목·요약·매칭 섹션 제목 상위 N | 지식. pg_trgm 유사도 + 태그 매칭 |
| `read_document` | documentId, sectionIds? 또는 grep? | 섹션 텍스트 (크기 상한) | 지식. 전체 읽기는 섹션 목록 먼저 |
| `find_person` | topic | 담당자 이름·역할·담당 영역 | 연결. 연락처는 반환하지 않음 |
| `propose_escalation` | question, topic, suggestedAssigneeId? | 미리보기 문구 | 연결. 실제 생성은 신입이 UI 에서 확인 |
| `review_submission` | taskInstanceId, submissionId | 루브릭 기준 피드백 (구조화) | 코치. 내부적으로 별도 호출 (§4.6) |

도구는 모두 서버에서 실행된다. 에이전트는 DB 에 직접 쓰지 않고 도구를 통해서만 쓴다.

### 4.4 메모리
- 신입별 `AgentMemory.summary` 하나. 대화가 끝날 때(또는 N턴마다) 에이전트가 갱신한다.
- 담는 것: 트랙 진행 맥락, 반복해서 막히는 주제, 선호하는 설명 방식.
- 담지 않는 것: 대화 원문, 개인 사정, 평가성 표현. 요약 생성 프롬프트에 금지 목록을 둔다.
- 긴 대화는 SDK 의 서버 측 컴팩션(베타) 또는 자체 요약으로 자른다. 어느 쪽이든 응답의 `content` 전체를 이력에 보존한다.

### 4.5 질문 로그와 에스컬레이션
```
신입 질문 ──▶ 에이전트 답변 (도구 호출·인용)
                │
                ├─ 턴 종료 후 별도 호출(구조화 출력): { normalizedQuestion, topic, answered, citedDocIds }
                │     → QueryLog 저장.  normalizedQuestion 은 이름·개인 맥락 제거한 일반형
                │
                └─ answered=false 이고 신입이 전달에 동의 ──▶ Escalation 생성 (assignee = find_person 결과 또는 멘토)
                                                              │
                                              담당자 답변 ──▶ 신입에게 표시 + DocDraft 생성 (제목·본문 초안)
                                                              │
                                              운영자 수락 ──▶ Document(source=MANUAL) 등록 → 다음 질문부터 인용 가능
```
- 운영자 공백 리포트는 `topic` 별 미응답 건수와, 에스컬레이션된 `normalizedQuestion` 만 보여준다. 답변된 질문의 문구는 보여주지 않는다.

### 4.6 과제 검토 (코치)
- 제출 시점에 별도 호출. 입력: 과제 설명, 루브릭(`TaskTemplate.rubric`), 참고 문서 섹션, 제출물.
- 출력(구조화): `{ verdict: PASS|REVISE, findings: [{ item, severity, quote?, suggestion }], summary }`.
- 교육 트랙 루브릭은 `AGENTS.md` §5 체크리스트와 §4 문체 규칙을 항목화한 것. 플랜 md 의 "평가 기준" 열에서 가져온다.
- 코치는 **점수를 매기지 않는다.** PASS/REVISE 와 항목별 근거만. 멘토 메모는 별도 필드.

### 4.7 주간 요약
- 매주 월요일 아침 배치. 입력: 지난 주 과제 상태 변화, 기한 초과, BLOCKED 사유(신입이 적은 것), QueryLog 의 topic 집계.
- 원문·normalizedQuestion 은 입력에 넣지 않는다. 출력은 멘토 현황 화면과 멘토에게만.

## 5. 지식 파이프라인

### 5.1 소스와 가져오기
| 소스 | 대상 | 방법 | MVP |
|---|---|---|---|
| Google Drive | 화이트리스트 폴더의 hwpx·docx·md·pdf | 운영자 맥에서 `ingest` 스크립트가 마운트를 읽어 서버에 푸시. 2단계: 서버에서 Drive API 서비스 계정 | 푸시 |
| GitHub | 지정 리포의 `*.md` (README, AGENTS.md, docs/) | GitHub API, 토큰은 읽기 전용 | 포함 |
| 수동 | 콘솔 업로드 md, 에스컬레이션 답변에서 수락된 초안 | 콘솔 | 포함 |
| 리포 `knowledge/` | 플랜이 참조하는 사내 문서 초안(회사소개·도구 세팅·근무규정·커뮤니케이션·교육 운영·과정 카탈로그·자사 제품·플랫폼 사용법) | `ingest.py --source github --root knowledge` | 포함 |

### 5.2 변환
1. hwpx·docx → `_보고서도구/doctext.py` 로 텍스트. pdf → `pdftotext`. md 는 그대로.
2. 섹션 분할: 제목 기호(`Ⅰ.` `1.` `□` `#`)와 표 경계로 나눈다. 표는 `|` 구분 텍스트로 유지.
3. 문서당 Claude 호출 1회: 제목 정규화, 한 줄 요약, 태그 5개 이내, **개인정보 포함 여부** 판정.
4. `contentHash` 가 같으면 건너뛴다. 바뀐 문서만 재처리.

### 5.3 개인정보·고객정보 필터
- 파일명 패턴 제외: `출석부`, `명단`, `연락처`, `개인정보`, `계약`, `견적`, `accessKeys`.
- 본문 패턴: 이메일·휴대전화·주민번호 형식이 섹션에 N건 이상이면 **그 섹션만 제외**하고 문서에 플래그.
- 3번 Claude 판정이 "포함"이면 운영자 확인 전까지 `visibility=ADMIN`.
- 결과보고서의 `참여자 명단` 표는 섹션 단위로 걸러진다. 보고서 자체는 양식 학습용으로 유효하므로 남긴다.

### 5.4 검색 방식 (임베딩 없음)
- 1차: 시스템 프롬프트의 **카탈로그** 를 보고 에이전트가 문서를 고른다.
- 2차: `search_documents` 가 `pg_trgm` 유사도(제목·요약·태그·섹션 제목)로 보강한다.
- 3차: `read_document` 로 섹션을 읽는다. 한 번에 읽는 크기에 상한을 둔다.
- 문서가 수백 건을 넘거나 재현율이 떨어지면 Voyage AI 임베딩을 `DocSection` 에 추가한다 (2단계).

### 5.5 가시성
`Document.visibility`: `ALL` (전 직원) · `TRACK` (해당 트랙 온보딩 중인 신입과 멘토·운영자) · `ADMIN` (운영자만, 인덱싱만 되고 답변에 안 씀).
`search_documents` 와 `read_document` 는 요청자 권한으로 필터한다. 에이전트는 권한 밖 문서의 존재를 모른다 (카탈로그도 권한별로 조립).

## 6. 가시성·개인정보 규칙

| 데이터 | 신입 본인 | 멘토 | 운영자 |
|---|---|---|---|
| 대화 원문 (`Message`) | 읽기 | 없음 | 없음 (DB 직접 접근 제외) |
| 에이전트 메모리 요약 | 읽기 | 없음 | 없음 |
| 과제 상태·제출물·코치 피드백 | 읽기·쓰기 | 읽기·메모 | 읽기 |
| `QueryLog.normalizedQuestion` | — | 에스컬레이션된 것만 | 에스컬레이션된 것만 |
| `QueryLog.topic` 집계 | — | 담당 신입 | 전체 |
| 주간 요약 | 읽기 | 읽기 | 읽기 |
| 사람 디렉터리 연락처 | 이름·역할만 | 이름·역할만 | 편집 |

- 원칙: **원문에서 파생된 것은 원문을 보지 않고 만든다.** 주간 요약·공백 리포트의 입력에 `Message` 가 들어가지 않는다.
- 보존: 온보딩 완료 후 `[[추후기입: 보존 기간, 예 90일]]` 지나면 `Message` 삭제. `QueryLog` 는 익명 집계만 남긴다.
- 감사: 운영자 행위(가시성 변경, 초안 수락, 온보딩 개설)는 `AuditLog`.

## 7. 수용 기준 (MVP 완료 정의)

- [ ] nxtcloud.kr 이메일로 가입·로그인하면 역할에 맞는 첫 화면이 뜬다. 다른 도메인은 가입이 거부된다.
- [ ] 운영자가 `plans/공통트랙.md` · `plans/교육트랙.md` 를 가져와 온보딩을 개설하면 기한 계산된 과제가 생성된다.
- [ ] 신입이 "결과보고서 양식 A·B 차이" 를 물으면 `AGENTS.md` 섹션을 인용한 답이 스트리밍으로 온다.
- [ ] 사내 문서에 없는 질문에는 "찾지 못했다" 와 전달 제안이 나오고, 동의 후 에스컬레이션이 생성된다.
- [ ] 멘토가 에스컬레이션에 답하면 신입 화면에 답이 보이고 운영자에게 문서 초안이 생긴다.
- [ ] 과제 제출 시 루브릭 기반 PASS/REVISE 피드백이 온다.
- [ ] 멘토 화면에서 대화 원문을 볼 수 있는 경로가 **없다** (API 포함).
- [ ] 참여자 명단이 들어 있는 보고서를 동기화하면 명단 섹션은 제외되고 나머지는 검색된다.
- [ ] 주간 요약이 생성되고 입력에 `Message` 가 포함되지 않음을 코드로 확인한다.
